# 課題 3 — ボタンで点滅の間隔を変える

課題 2 のコードから始めて、ユーザーボタンで LED の点滅の速さを変えられるように
します。作業する場所は [`main.c`](main.c) です。

<!-- section: functional-specification -->
## 機能仕様

プログラムが満たすべき動作です。

- 課題 2 と同じく、緑の LED（LD2）がタイマーで点滅すること。
- ユーザーボタンを押すと、点滅の速さが変わること。
- 速さの変え方は自由です。2 つの速さを交互に切り替えても、3 つを順に回しても、
  押している間だけ速くしてもかまいません。
- 点滅を作るのは引き続きタイマーであること。ボタンが変えるのは速さであって、
  点滅させる仕組みそのものではありません。

<!-- section: implementation-specification -->
## 実装仕様

その動作を作るために使うものです。レジスタの名前は示しますが、値は示しません。
値を見つけることがこの課題です。

- B1、基板の青いボタンは PC13 につながっています。
- PC13 は LED とは別のポートにあるため、クロックは同じレジスタの別のビットです。
- PC13 を入力にすること。`GPIOx_MODER` のどの値かです。
- 入力ピンの状態を読むレジスタを使うこと。課題 1 で書き込んだレジスタとは別です。
- **ボタンは押していないとき High を読みます。** プルアップ抵抗が PC13 を High
  に保ち、押すとピンがグランドにつながります。つまり押された状態はゼロであって、
  イチではありません。ここはほとんどの人が一度は引っかかります。
- 点滅の速さを変えるのは、遅延ループではなくタイマーを変えることです。リロード値
  を保持するレジスタはどれか、そして動作中のタイマーにそれを書き込むと何が起きる
  かです。
- GPIO ポート C のクロックを有効にすること。

ボタンに気づく方法は 2 つあります。

**ポーリング** — メインループでピンを読みます。単純で、この課題には充分です。

**割り込み** — EXTI を通じて、ピン自身に割り込ませます。手間は増えますが、実際の
製品の作り方に近いです。ハンドラの名前は `EXTI15_10_IRQHandler` になります。PC13
はピン十番から十五番までと割り込みを共有しているためです。

どちらもこの課題の正しい答えです。

**ポーリングするなら、読み取りの間に短いディレイを入れてください。**

```
while (1) {
    wait_a_little();         // 小さなディレイで充分です
    // ここでボタンを読みます
}
```

実機では、ピンをできるだけ速く読み続けるループは単に無駄なだけです。シミュレータ
ではそれよりもずっと悪いことになります。周辺レジスタの読み取りはシミュレートする
のに高くつくため、ほかに何もしないループは実時間よりはるかに遅く動きます。1 秒の
点滅が数分に一度しか来なくなり、完全に正しいプログラムが壊れて見えます。

測定値: 詰めたポーリングで実時間の 156 倍遅く。同じコードに読み取りの間の短い
ディレイを入れて 2.5 倍。下の `peripheral-reads-are-slow-to-simulate` の行です。

## シミュレータと実機の違い

<!-- generated: divergences -->
<!-- このブロックは divergences.json から生成されています。手で編集せず、python tools/gen_exercise_pages.py を実行してください -->

**誤ったコードが正しく見えてしまう点です。**ここではシミュレータのほうが実機より寛容なため、何も知らせてくれません。

- **pin-configuration-not-enforced** — バスコントローラは GPIO のレジスタを一切参照しません。I2C モデルはポートモードも代替機能もクロック有効ビットも読まないため、使うはずのピンを全く設定していなくても通信が成立します。2026-09-25 に確認: GPIOB への書き込みをすべて削除した firmware でも Si7021 を正しく読み取れました
  実機では: 周辺機能がピンに届くのは、そのピンを経由する場合だけです。ポートのクロックを有効にし、ピンを代替機能モードにし、正しい代替機能を選ぶ必要があります。どれか一つでも欠ければ、バスには何も届きません
- **superset-peripherals** — 汎用の STM32F4 プラットフォームは F401RE が持たない周辺機器を宣言しています。Ethernet MAC、CAN1 と CAN2、GPIO ポート F から K、UART4 と UART5、外部メモリコントローラ、そして TIM6、TIM7、TIM8、TIM12、TIM13、TIM14 です。上書きでは削除できないため、使用できてしまいます
  実機では: STM32F401RE が持つのは GPIO ポート A から E と H、USART 3 系統、タイマー TIM1 から TIM5 と TIM9 から TIM11 です。CAN、Ethernet、外部メモリコントローラはありません

そのほか、知っておく価値のある違いです。

- **cpu-speed-not-from-the-clock-tree** — プロセッサは毎秒 1 億命令という固定速度で実行します。
- **peripheral-reads-are-slow-to-simulate** — 周辺レジスタの読み出しは、変数の読み出しに比べて大きなコストがかかります。
- **static-timer-clocks** — 周辺クロックは RCC と PLL のレジスタから導出されません。

それぞれの全文は [`DIVERGENCES.ja.md`](../../DIVERGENCES.ja.md) にあります。

## 合否の判定

動作をどう見るかです。満たすべき動作そのものは上の「機能仕様」にあります。

設計が自由なので、確認はどの答えにも共通する点だけを見ます。ボタンを押す前と後で
点滅の速さを測り、違っていることを見ます。あわせて TIM2 のレジスタを読み、動作を
続けているかを見ます。

さらに、確認は途中で TIM2 を停止させます。そのとき LED も止まる必要があります。
この課題は課題 2 の続きなので、点滅を作るのは引き続きタイマーです。

ピンの設定は見ません。どちらのピンについてもです。課題 1 では見ますが、ここでは
見ていません。PA5 の出力も PC13 の入力も、誤っていても無くても、シミュレータでは
この課題は正しく動きます。実機では動きません。

ビルドしたあと、コンテナの中で自分でも実行できます。

```
python3 exercises/03-change-the-interval/check.py \
  --elf exercises/03-change-the-interval/firmware.elf
```

課題の求めるとおりに動いていれば `0`、動いていなければ `1`、判断できなければ
`2` を返します。2 は不合格ではありません。判断できるところまで進めなかったと
いう意味で、たいていはまだビルドしていないためです。
