# 課題 4 — I2C でセンサーを読み、LED に表示する

I2C で温度センサーを読み、その値を複数の LED に表示します。作業する場所は
[`main.c`](main.c) です。

<!-- section: functional-specification -->
## 機能仕様

プログラムが満たすべき動作です。

- Si7021 温度センサーを I2C で読むこと。
- 読んだ値を 4 つの LED にバーとして表示すること。寒いほど点灯数が少なく、
  暖かいほど多くなります。
- しきい値は自分で決めてかまいませんが、0 〜 45 度の範囲に入れること。確認が
  その範囲を動かすため、外側のしきい値は一度も超えられません。
- 同じ温度に戻れば、表示も同じに戻ること。

<!-- section: implementation-specification -->
## 実装仕様

その動作を作るために使うものです。レジスタの名前は示しますが、値は示しません。
値を見つけることがこの課題です。センサーのアドレスとコマンドバイト、そして
変換式は与えられていて、`main.c` に書いてあります。

- センサーは I2C1 につなぎます。I2C1 は Arduino コネクタの D15（PB8）が SCL、
  D14（PB9）が SDA としてすでに出ているため、ピンを選ぶ余地はありません。
- I2C1 のクロックは APB1 にあります。
- 2 本のピンの代替機能を、I2C を意味するものに設定すること。`GPIOx_AFRH` と、
  データシート（DS10086）の代替機能表です。リファレンスマニュアルではありません。
- 2 本のピンをオープンドレイン出力にすること。実機のバスはこれなしでは動きません。
- I2C 周辺機能に、入力クロック周波数、速度設定、立ち上がり時間を与えてから有効に
  すること。`I2C_CR2`、`I2C_CCR`、`I2C_TRISE` です。
- このセンサーの読み取りは、スタート、書き込みビット付きアドレス、コマンドバイト、
  リピーテッドスタート、読み出しビット付きアドレス、そして上位バイトから 2 バイト
  です。各段階がどう応答されるかは `I2C_SR1` で見ます。
- 変換はデータシートの式で行うこと。浮動小数点は有効になっていないため、固定小数点
  で計算します。度の百分の一を単位にし、途中の値は `uint32_t` に保ちます。
- LED のピンを出力にすること。基板自身の PA5 と、自分で追加した 4 つです。位置は
  `main.c` に書いてあります。

I2C の転送だけはライブラリを使ってもかまいません。GPIO、タイマー、変換は自分で
書く部分です。

<!-- section: before-you-start -->
## 始める前に

ボード画面を開き、部品を 2 つ追加してください。ボードには利用できる LED が 1 つ
あるだけで、センサーはありません。実機の NUCLEO-F401RE にもセンサーはないため、
自分で載せるまでどちらも存在しません。

- **Si7021** 温度センサー。I2C1 に接続します
- **LED をあと 4 つ**。表示のバーに使います

実機ならここでブレッドボードを出すところです。センサーを 2 つの穴に、LED を 4 つ
の穴に抵抗付きで配線します。追加した部品は自分の `board.repl` に書き込まれるため、
コードが動くボードは自分で組み立てたボードになります。2 つとも載せるまで、この課題
は動きません。

## シミュレータと実機の違い

<!-- generated: divergences -->
<!-- このブロックは divergences.json から生成されています。手で編集せず、python tools/gen_exercise_pages.py を実行してください -->

**誤ったコードが正しく見えてしまう点です。**ここではシミュレータのほうが実機より寛容なため、何も知らせてくれません。

- **open-drain-ignored** — GPIO モデルは出力タイプレジスタを一切見ません。オープンドレインを選ぶために OTYPER に書き込んでも 'Unhandled write to offset 0x4 ... Tags: OT8 (0x1), OT9 (0x1)' が出るだけで、何も変わりません。バスのピンをオープンドレインに設定してもしなくても、I2C 通信は成功します
  実機では: I2C はワイヤード AND のバスです。SCL と SDA の両方をオープンドレインにしてプルアップする必要があります。デバイスはラインを Low に引くことで信号を送り、離すと High に戻るためです。プッシュプル出力では衝突し、バスは動作しません
- **pin-configuration-not-enforced** — バスコントローラは GPIO のレジスタを一切参照しません。I2C モデルはポートモードも代替機能もクロック有効ビットも読まないため、使うはずのピンを全く設定していなくても通信が成立します。2026-09-25 に確認: GPIOB への書き込みをすべて削除した firmware でも Si7021 を正しく読み取れました
  実機では: 周辺機能がピンに届くのは、そのピンを経由する場合だけです。ポートのクロックを有効にし、ピンを代替機能モードにし、正しい代替機能を選ぶ必要があります。どれか一つでも欠ければ、バスには何も届きません
- **sensor-value-quantisation** — SI70xx モデルは温度と湿度を固定小数点に変換して保持するため、読み出した値は設定した値とわずかに異なります。25.00 C を設定して firmware から読むと 24.99 C になりました
  実機では: 実際の Si7021 も量子化しますが、その分解能と誤差は固有のもので、モデルが行う丸めとは一致しません
- **superset-peripherals** — 汎用の STM32F4 プラットフォームは F401RE が持たない周辺機器を宣言しています。Ethernet MAC、CAN1 と CAN2、GPIO ポート F から K、UART4 と UART5、外部メモリコントローラ、そして TIM6、TIM7、TIM8、TIM12、TIM13、TIM14 です。上書きでは削除できないため、使用できてしまいます
  実機では: STM32F401RE が持つのは GPIO ポート A から E と H、USART 3 系統、タイマー TIM1 から TIM5 と TIM9 から TIM11 です。CAN、Ethernet、外部メモリコントローラはありません

## 合否の判定

動作をどう見るかです。満たすべき動作そのものは上の「機能仕様」にあります。

しきい値は自分で決めるため、「この点灯パターンが正解」というものはありません。
代わりに形を見ます。センサーが暖かくなるにつれて、点灯する LED の数が減らない
こと、そして範囲のどこかで増えることです。それがバーであるということであり、
しきい値を教えずに確認できます。

温度は昇順では与えません。また、最後にもう一度、最初と同じ温度に戻します。その
とき表示も最初と同じに戻る必要があります。時間が経つほど点灯数を増やすだけの
プログラムは、上がる一方の並びなら完全なバーを描けますが、下がる並びには追従でき
ませんし、元に戻ることもできません。

I2C のピンも見ます。GPIOB のクロック、PB8 と PB9 が代替機能モードであること、
そして選んでいる代替機能が正しいことです。オープンドレインは見ません。シミュ
レータがその書き込みを受け付けず、読み返せないためです。実機では必要です。

ビルドしたあと、コンテナの中で自分でも実行できます。

```
python3 exercises/04-read-the-sensor/check.py \
  --elf exercises/04-read-the-sensor/firmware.elf
```

課題の求めるとおりに動いていれば `0`、動いていなければ `1`、判断できなければ
`2` を返します。2 は不合格ではありません。判断できるところまで進めなかったと
いう意味で、たいていはまだビルドしていないためです。
